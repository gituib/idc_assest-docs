权限接口 ​

权限接口提供系统的三级权限树查询能力，是 RBAC 角色配置的数据基础。

历史说明：本文档此前为空。权限相关接口分为两部分——权限字典查询（本页）与角色 CRUD（见 用户与角色接口）。

权限模型 ​

系统采用三级权限结构：

模块（module）
  └── 菜单（menu）
        └── 按钮（button）
层级type 取值说明示例
模块module一级功能域，通常不单独授权device、room、system
菜单menu对应一个前端页面路由device:view、rack:3d、ipam:view
按钮button页面内的操作能力device:create、device:edit、device:delete

权限码命名规范为 {资源}:{操作}，例如 ticket:view、consumable:stats、warehouse:delete。

权限码实现机制 ​

中间件 ​

后端通过 requirePermission(code) 中间件在路由级声明权限要求：

js
router.post('/', authMiddleware, requirePermission('device:create'), async (req, res) => { ... });

通配符支持 ​

权限匹配支持通配符：

权限值含义
*全部权限（admin 角色使用）
device:*设备模块全部操作

权限种子数据 ​

权限清单以种子数据形式维护于 backend/scripts/init-permissions.js，服务启动时执行幂等 upsert，补齐缺失的权限项，不会覆盖已存在的自定义权限。

bash
# 手动初始化权限种子
cd backend && npm run init-permissions

启动期自检：服务启动后会扫描所有路由的 requirePermission 声明，若发现权限码在种子中缺失，会输出警告日志。这是发现权限漏配的主要手段。

获取权限列表 ​

http
GET /api/permissions

鉴权要求 ​

  • 需要有效令牌（authMiddleware）
  • 不额外校验模块级权限码：任何已登录用户均可读取权限字典，以便前端渲染角色配置界面

响应示例 ​

json
{
  "success": true,
  "data": [
    {
      "permissionId": "perm_device_view",
      "permissionName": "设备查看",
      "permissionCode": "device:view",
      "parentId": "device",
      "type": "menu",
      "sort": 10,
      "status": "active"
    },
    {
      "permissionId": "perm_device_create",
      "permissionName": "设备新增",
      "permissionCode": "device:create",
      "parentId": "device",
      "type": "button",
      "sort": 11,
      "status": "active"
    }
  ]
}

字段说明 ​

字段类型说明
permissionIdstring (PK)主键
permissionNamestring权限名称（中文）
permissionCodestring权限码，中间件校验依据
parentIdstring父权限 ID，module 级为空
typeenummodule、menu、button
sortinteger排序值，用于树形渲染顺序
statusenumactive、inactive；接口仅返回 active 项

数据结构提示 ​

接口返回扁平数组（按 sort 升序），前端需按 parentId 自行构建树形结构。服务端不返回嵌套树。

未纳入权限码的模块 ​

以下模块当前未在种子数据中注册独立权限码，所有已登录用户均可访问：

模块前端路由权限配置说明
IPAMNO_PERMISSION_REQUIREDApp.jsx 中已标注「IPAM 在 init-permissions.js 清单中暂无对应权限码」

改进建议：如需按角色隔离 IPAM 访问，需在 init-permissions.js 中新增 ipam:view / ipam:edit 等权限码，并在 frontend/src/App.jsx 的路由表与 backend/routes/ipam.js 中各路由上接入。这是当前权限体系的主要缺口。

权限校验失败行为 ​

后端 ​

返回 403：

json
{
  "success": false,
  "message": "无权限执行此操作"
}

前端 ​

  • 菜单项按权限码条件渲染，无权限的菜单不显示
  • 路由层由 ProtectedRoute 拦截，无权限跳转 /403
  • 按钮级操作按权限码禁用或隐藏
