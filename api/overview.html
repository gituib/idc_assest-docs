API 概览 ​

接口基础规范 ​

项目规范
基础URLhttp://localhost:8000/api（开发环境） / https://<域名>/api（生产环境，Nginx 反向代理）
认证方式JWT Bearer Token（单一访问令牌）
Content-Typeapplication/json
字符编码UTF-8
时间格式ISO 8601（如 2026-06-17T08:30:00Z）
接口版本与项目版本一致，当前 v2.8.4

认证流程 ​

系统采用 JWT 进行身份认证，整体流程如下：

1. 客户端 POST /api/auth/login 提交账号密码
2. 服务端校验通过后返回 token 与用户信息（含角色权限码）
3. 客户端将 token 持久化存储
4. 后续请求在请求头携带：Authorization: Bearer <token>
5. 令牌有效期由 TOKEN_EXPIRY 控制（默认 24h），过期后需重新登录
6. 改密 / 重置密码 / 禁用 / 退出登录会递增 tokenVersion，此前令牌立即失效

重要：系统不使用双令牌（accessToken + refreshToken）模型，不存在 /api/auth/refresh 端点。令牌过期后客户端应清除本地状态并跳转登录页。

请求头示例 ​

http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json

免鉴权端点白名单 ​

全局认证中间件挂在 app.use('/api', authMiddleware)，仅以下精确匹配的 method + path 组合可匿名访问：

方法路径
POST/api/auth/login
POST/api/auth/register
POST/api/auth/check-admin
POST/api/auth/forgot-password/send-code
POST/api/auth/forgot-password/reset
POST/api/auth/unlock
GET/api/port-options
GET/api/maintenance/status
GET/api/system-settings/system/info
POST/api/frontend-logs

另有 /p/devices/:deviceId（公开设备信息牌）与 /health 不在 /api 前缀下，天然免鉴权。

设计说明：白名单使用精确匹配而非前缀匹配。旧实现按整棵子树放行，导致 /api/maintenance/disable 等写端点可被匿名调用；现在改为精确匹配以修复该缺陷。

通用约定 ​

分页参数 ​

多数列表接口支持以下分页参数：

参数类型默认值说明
pagenumber1当前页码，从 1 开始
pageSizenumber20每页条数

每页上限并非全局统一

MAX_PAGE_SIZE（backend/config/constants.js，默认 1000）目前只被 GET /api/users 使用（routes/users.js 中 Math.min(pageSize, PAGINATION.MAX_PAGE_SIZE)）。/api/inventory、/api/consumables 等接口只用到 DEFAULT_PAGE_SIZE，没有上限钳制。

也就是说「上限 500」是旧文档的误写，实际既不是 500、也不是全局限定。需要稳定行为时请在请求侧自行限制 pageSize。

分页响应格式 ​

json
{
  "success": true,
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 20,
    "totalPages": 5
  }
}

注意：并非所有接口都遵循该结构。以下为已知差异：

  • IPAM 接口：data.list + data.pagination.{page, pageSize, total, totalPages}
  • 库房 / 空闲设备接口：不使用 success 包装，直接返回 { total, warehouses|idleDevices|devices, page, pageSize }，错误时返回 { error: "..." }
  • 设备端口接口：字段名依具体端点而定，device-ports 列表返回 { success, data: { list, pagination } }

对接具体接口时请以对应文档为准。

列表筛选 ​

列表接口普遍支持以下通用筛选参数（具体以各模块文档为准）：

参数类型说明
keywordstring关键词模糊搜索（名称、编号、序列号等）
statusstring状态筛选，传 all 表示不筛选
startDate / endDatestring时间范围（ISO 8601）

响应格式 ​

成功响应 ​

json
{
  "success": true,
  "data": {},
  "message": "操作成功"
}

失败响应 ​

json
{
  "success": false,
  "message": "错误描述"
}

404 兜底：未匹配任何路由的 /api 请求返回统一 JSON（替代 Express 默认 HTML）：

json
{
  "success": false,
  "error": { "code": "NOT_FOUND", "message": "请求的资源不存在" }
}

错误脱敏 ​

生产环境下，服务端不会将 error.message 原文回显给客户端（除驱动层已明确定义的业务诊断信息外），真实原因仅写入服务端日志。对接时应以 HTTP 状态码与固定文案判断错误类型。

状态码 ​

HTTP 状态码 ​

状态码说明
200请求成功
201资源创建成功
400请求参数错误
401未认证或令牌失效
403无权限访问 / 账号锁定 / 账号禁用
404资源不存在
409资源冲突（如唯一性校验失败、U 位冲突、端口已被接线占用）
423系统维护中
429触发频率限制
500服务器内部错误
503服务不可用（维护模式登录拦截、健康检查异常）

维护模式 ​

系统开启维护模式后，除管理员外的所有用户无法访问业务接口：

json
{
  "success": false,
  "message": "系统维护中，请稍后再试",
  "code": "MAINTENANCE_MODE"
}

相关端点：

方法路径说明
GET/api/maintenance/status查询维护状态（免鉴权）
POST/api/maintenance/disable手动解除维护模式（仅超管）

健康检查 ​

方法路径鉴权说明
GET/health免鉴权仅返回 { "status": "ok" }；生产环境不暴露时间戳、Node 版本、内存等指纹信息
GET/api/health/detail超管返回完整健康检查结果（数据库、JWT 配置、磁盘、内存等）

Swagger 文档 ​

后端启动后，仅在非生产环境可访问 Swagger UI：

http://localhost:8000/api-docs
端点说明
/api-docsSwagger UI 交互式界面
/api-docs.jsonOpenAPI 规格 JSON

生产环境不挂载 Swagger：完整 OpenAPI 规格包含全部端点与参数，属信息泄露风险，server.js 中通过 NODE_ENV !== 'production' 条件排除。需要在线调试时请在开发或预发环境进行。
