# 端口自动采集

端口自动采集通过登录交换机或服务器 BMC，读取设备真实的端口与硬件配置，与系统台账比对后按差异落库，避免逐条手工录入。

> **版本要求**：需 **v2.8.0 及以上**。v2.8.2 补齐了批量落库的四向冲突检查。

## 适用场景

| 场景 | 推荐方式 | 说明 |
|------|----------|------|
| 新交换机上架 | SSH / SNMP 采集 | 一次性同步全部端口与状态 |
| 服务器上架 | Redfish 带外采集 | 同时获得硬件清单（CPU/内存/硬盘/网卡） |
| 定期核对 | 重新采集比对差异 | 发现现场改配后未同步的端口 |
| 板卡扩容 | 重新采集 | `added` 分区即为新增端口 |
| 拆板卡 / 换设备 | 重新采集 | `removed` 分区即为已消失端口 |

## 采集前准备

### 1. 网络可达性

采集主机（后端服务所在服务器）必须能访问目标设备：

| 协议 | 默认端口 | 目标类型 |
|------|----------|----------|
| SSH | 22 | 交换机、路由器、防火墙 |
| Telnet | 23 | 老旧网络设备 |
| SNMP | 161 (UDP) | 任意支持 SNMP 的网络设备 |
| Redfish | 443 / 80 | 服务器 BMC（iDRAC / iLO / iBMC） |

验证方式（在采集主机上执行）：

```bash
# SSH
telnet 10.10.1.11 22

# SNMP（需安装 snmpwalk）
snmpwalk -v2c -c public 10.10.1.11 sysDescr

# Redfish
curl -k https://10.10.1.20/redfish/v1
```

### 2. 采集账号

建议**为采集单独创建只读账号**，不要使用管理员账号：

| 设备类型 | 所需权限 | 举例（华为） |
|----------|----------|--------------|
| 华为交换机 | 网络只读 + `display` 命令 | `local-user netadmin password irreversible-cipher ...` / `local-user netadmin privilege level 1` |
| H3C 交换机 | `network-operator` 角色 | `local-user netadmin` / `authorization-attribute user-role network-operator` |
| Cisco 交换机 | privilege 15 或自定义只读视图 | `username netadmin privilege 15 secret ...` |
| 锐捷交换机 | 只读权限 | `username netadmin privilege 1` |
| 服务器 BMC | 只读 / Operator | iDRAC：Setup → User Accounts → 角色设为 `Operator` |

### 3. SSRF 防护检查

采集目标受系统级安全策略约束：

| 系统设置项 | 默认值 | 说明 |
|------------|--------|------|
| `allow_intranet_collection` | `true` | 是否允许访问私网目标。**关闭后拒绝所有私网地址，会中断核心采集业务** |
| `target_whitelist` | 空数组 | 非空时，私网目标必须落在白名单 CIDR 内 |

> 若采集报「目标地址不被允许」，请先检查这两项设置，而非账号问题。

## 操作流程

### 交换机端口采集

```
1. 设备管理 → 选择目标交换机 → 打开详情
2. 切换到「采集凭据」区块 → 新增凭据
   - 协议：SSH（推荐）或 SNMP
   - 地址、端口、用户名、口令
   - 厂商：可留空，系统会连接后自动识别
   - 勾选「设为默认凭据」
3. 点击「连接测试」验证凭据可用
4. 进入端口管理 → 选择该设备 → 点击「端口采集」
5. 系统返回差异预览：
   - 新增端口（设备有、系统无）
   - 变更端口（属性不一致，逐字段列出）
   - 多余端口（系统有、设备无）
6. 勾选需要落库的分区 → 执行应用
```

### 凭据连接测试结果解读

| 结果 | 含义 | 下一步 |
|------|------|--------|
| 连接成功 | 协议、账号、网络均正常 | 继续采集 |
| 认证失败 | 账号或口令错误 | 核对凭据；必要时用 `/raw` 端点读取明文比对 |
| 连接超时 | 网络不通或端口被拦 | 检查防火墙与路由 |
| 协议不匹配 | 设备不支持所选协议 | 更换协议（如从 SSH 改为 SNMP） |
| 厂商不支持 | 驱动未适配 | 手工填写厂商，或按通用模板采集 |

### 支持的厂商

| 厂商标识 | 设备类型 | 采集方式 |
|----------|----------|----------|
| `huawei` | 华为 | SSH / Telnet |
| `h3c` | H3C 华三 | SSH / Telnet |
| `cisco` | 思科 | SSH / Telnet |
| `ruijie` | 锐捷 | SSH / Telnet |
| `generic` | 通用 | SNMP（IF-MIB，厂商无关） |

> **厂商识别策略**：优先使用凭据中已配置的 `vendor`；未配置时，系统连接后执行 `display version` / `show version` 自动识别。SNMP 方式从 `sysDescr` 识别，识别失败退回 `generic` 且**不阻断采集**（IF-MIB 本身厂商无关）。

### 服务器带外采集

```
1. 设备管理 → 选择服务器 → 详情 → 采集凭据
   - 协议：redfish
   - 地址：BMC 管理地址（不是操作系统地址）
   - 用户名 / 口令：BMC 账号
2. 连接测试
3. 端口管理 → 该设备 → 「服务器采集」
4. 差异预览同时包含：
   - 硬件清单（CPU、内存、硬盘、电源、风扇、网络适配器）
   - 端口差异
5. 执行应用
```

**服务器采集的额外效果**：

| 结果 | 落库位置 |
|------|----------|
| 硬件清单 | `Device.customFields.hardware`（JSON） |
| 网络适配器 | 自动创建/更新 `NetworkCard` 记录，命名为 `网卡1`、`网卡2`… |
| 端口 | `device_ports` 表，按差异落库 |

> 已存在的同名网卡执行更新（型号/厂商/端口数/描述），**不会删除手工创建的其他网卡**，因此人工补充的网卡信息不会被采集覆盖。

## 差异分区处理建议

### 新增端口（added）

**默认落库**。建议全选，这是采集的主要价值。

### 变更端口（changed）

**默认落库**。常见变更：

| 变更字段 | 可能原因 |
|----------|----------|
| `portSpeed` | 更换光模块或协商降速 |
| `status` | 端口从 down 变为 up |
| `description` | 现场改了端口描述 |

> 若变更内容与你的台账语义冲突（例如 OFFICE 环境手工维护了业务描述，不希望被设备上的默认描述覆盖），可取消勾选 `changed`，仅落库新增端口。

### 多余端口（removed）

**默认不落库**。这是刻意的保守设计：

- 采集失败的部分结果可能造成「所有端口都消失」的误判
- 删端口会连带影响接线记录
- 建议在确认板卡确实拆除后，手工在端口管理页面删除

## 常见问题

**Q：采集结果显示端口数为 0 或只有管理口？**

可能原因：
1. 使用了 SNMP 但设备的 IF-MIB 未开放（部分设备需显式启用）
2. SSH 账号权限不足，无法执行 `display interface brief`
3. 设备处于堆叠/集群模式，主设备只能看到自身端口

处理：先用 `discover` 预览查看原始返回，确认是驱动解析问题还是设备侧限制。

**Q：应用差异时提示「非法的端口字段变更」？**

差异对象由前端回传，服务端会校验 `fieldChanges` 的字段名是否在允许清单内。该提示说明前端提交了非端口字段（如 `portId`、`deviceId`）。通常由旧版本前端缓存导致，刷新页面后重新采集即可。

**Q：采集会不会覆盖我手工录入的端口描述？**

`changed` 分区默认勾选时，设备侧的描述会覆盖系统内记录。若你依赖手工维护的业务描述，建议在应用时**取消勾选 `changed`**，或采集前先备份端口数据。

**Q：同一台设备可以配置多个凭据吗？**

可以。同一设备可对每种协议各有一条「默认凭据」，采集时未指定 `credentialId` 则自动使用对应协议的默认凭据。更换账号时新建凭据并设为默认即可，旧凭据可保留备用。

**Q：采集需要多长时间？**

取决于设备规模与协议：SSH 通常 5~30 秒（与端口数量正相关）；SNMP 约 3~10 秒；Redfish 服务器因需逐项查询硬件，通常 10~60 秒。

**Q：采集失败会留下脏数据吗？**

不会。`discover` 阶段完全不写库；`apply` 阶段在单个数据库事务中执行，任一步失败整体回滚。

## 安全注意事项

| 事项 | 建议 |
|------|------|
| 凭据存储 | 口令与 SNMP 团体名 AES-256-GCM 加密落库，接口返回掩码 |
| 明文读取 | 仅超级管理员可使用 `/raw` 端点，且会记入操作日志 |
| 账号权限 | 采集账号应为只读，避免误操作设备 |
| 网络隔离 | 采集主机与设备建议处于同一管理网段，通过防火墙限定来源 |
| 密钥轮换 | 若使用 `REMOTE_BACKUP_KEY` 独立密钥，轮换前须先执行 `scripts/migrate-remote-backup-cipher.js` 重加密存量凭据 |
