# IP 地址管理（IPAM）

IPAM 模块用于规划网段、分配 IP 地址并维护「IP ↔ 设备」的对应关系，替代传统的 Excel 台账方式。

> **版本要求**：IP 与设备关联能力需 **v2.8.3 及以上**；定时探测调度需 **v2.8.4 及以上**。

## 功能定位

| 能力 | 解决的问题 |
|------|------------|
| 网段规划与嵌套 | 用树形结构表达「数据中心 → 业务域 → 子网」的层次划分 |
| IP 地址台账 | 替代 Excel，记录每个地址的状态、用途、绑定设备 |
| 设备双向关联 | 从 IP 查设备，也从设备查 IP |
| 在线探测 | 感知地址是否存活，发现台账与实际不符的地址 |
| 冲突检测 | 新建网段时自动发现与已有网段的重叠 |

## 进入模块

菜单位置：**IP地址管理 → 网段与IP**

> **权限说明**：IPAM 模块当前**未注册独立权限码**，所有已登录用户均可访问。如需按角色隔离，请参见 [权限接口 - 未纳入权限码的模块](/api/permissions#未纳入权限码的模块)。

## 网段管理

### 创建网段

1. 进入「网段与IP」页面
2. 点击「新建网段」
3. 填写关键信息：

| 字段 | 必填 | 填写建议 |
|------|------|----------|
| 网段名称 | 是 | 使用业务语义命名，如「生产业务网-A栋」 |
| CIDR | 是 | 如 `10.10.0.0/24` 或 `2001:db8::/32`，支持下述两种地址族 |
| 网关 | 否 | 建议填写，便于后续识别 |
| VLAN ID | 否 | 与交换机配置对齐 |
| DNS | 否 | 多个用逗号分隔 |
| 默认用途 | 否 | 设为 `management` 后，该网段内新建 IP 时自动推荐为带外管理地址 |
| 父网段 | 否 | 用于构建层级结构 |

4. 保存前系统自动执行 CIDR 解析与冲突检测，冲突时给出具体的冲突网段名称与 CIDR

### CIDR 解析规则

| 地址族 | 可用主机数计算 | 说明 |
|--------|----------------|------|
| IPv4 | `2^(32-前缀) - 2` | 扣除网络地址与广播地址 |
| IPv6 | `2^(128-前缀)` | 不使用广播地址概念 |

> IPv6 的 `/64` 网段可用主机数为 `2^64`，数值超出 JavaScript Number 精度范围，系统统一以字符串存储与展示。

### 网段嵌套规则

| 操作 | 是否允许 |
|------|----------|
| 在已有网段内创建更小的子网段 | **允许** |
| 创建与已有网段完全相同的 CIDR | 拒绝 |
| 创建与已有网段部分重叠的 CIDR | 拒绝 |
| 创建覆盖已有网段的大网段 | 拒绝 |
| 跨地址族（IPv4 与 IPv6） | 不参与冲突检测 |

### 层级统计规则

父网段的已用 IP 数**包含所有后代网段**的已用数（递归累加）。

```
10.0.0.0/16（父）  已用 240
  ├─ 10.0.1.0/24   已用 200
  └─ 10.0.2.0/24   已用 40
```

因此，父网段使用率反映的是整个地址池的实际占用，而非仅父网段直接挂载的 IP。

### 大规模网段处理

对于 `/16` 及以上的 IPv4 网段，系统不会一次性生成全部 IP 记录：

- 网段创建时按需生成，`autoGenerated` 标记是否已完成生成
- 网段详情页的统计按钮触发**按需统计**（`GET /subnets/{id}/stats`），避免全量扫描
- IPv6 网段恒不自动生成（`autoGenerated = false`），需按实际分配逐个添加

## IP 地址管理

### IP 状态

| 状态 | 含义 | 使用建议 |
|------|------|----------|
| 空闲 | 可使用 | 新设备分配时优先选择 |
| 已使用 | 已分配 | 通常由绑定操作自动设置 |
| 预留 | 预留给特定用途 | 如预留扩展、灾备 |
| 网关 | 网关地址 | 系统级保护，绑定中的 IP 不可改为该状态 |
| 排除 | 排除地址 | 如 VRRP 虚拟地址、不可扫描的地址 |

### 状态自动驱动机制

这是 IPAM 的核心设计，避免用户漏改状态导致台账失真：

```
IP 状态 = free，执行绑定 → 状态自动变 used，标记 statusAutoDriven = true
                                  │
                    执行解绑 ────┴──→ 因 statusAutoDriven = true，状态自动回退 free
```

| 场景 | `statusAutoDriven` | 解绑后状态 |
|------|--------------------|------------|
| 绑定前为 `free` | 置 `true` | 自动回退 `free` |
| 用户手动改过状态 | 置 `false` | 保持用户设置的状态不变 |

> 用户手动修改状态即视为「接管」该 IP 的状态控制权，系统不再自动干预。

### IP 类型（ipType）

| 类型 | 中文 | 典型场景 |
|------|------|----------|
| `management` | 带外管理 | BMC / iDRAC / iLO 管理口 |
| `business` | 带内业务 | 操作系统业务网卡 |
| `public` | 公网 | NAT 映射后的公网地址 |
| `storage` | 存储网 | 存储专用网络 |
| `other` | 其他 | 特殊用途 |

**网段默认用途的继承**：若网段设置了 `purpose`，在该网段内新建 IP 或绑定设备时，系统自动推荐该值，减少重复填写。

### 自定义标签

`customTag` 为自由文本，用于标注业务语义，如：

- `VIP` — 虚拟 IP
- `主备` — 主备切换组
- `cluster` — 集群地址
- `临时` — 临时分配

### 主 IP 标记

每台设备**全局最多一个**主 IP（`isPrimaryForDevice`），在表格中以 ★ 标识。

典型场景：一台服务器有管理 IP、业务 IP、存储 IP，其中管理 IP 通常设为主 IP，便于其他模块（如工单、拓扑）引用「设备地址」时优先取用。

设置新的主 IP 时，原主 IP 自动取消标记。

### 绑定与解绑

**单个绑定**：

1. 在 IP 列表中选择目标地址
2. 点击「绑定设备」
3. 选择设备，可选填 IP 类型与自定义标签
4. 如需设为主 IP，勾选「设为主 IP」

**批量绑定**：选中多个 IP 后统一指定目标设备，适用于一台服务器上多个连续的地址。

**解绑**：点击「解绑」，系统按状态自动驱动规则处理 IP 状态。

### 设备删除的级联处理

删除设备时，IPAM 自动执行：

| 处理项 | 行为 |
|--------|------|
| 绑定关系 | 清空所有关联 IP 的 `deviceId`、`networkCardId`、主 IP 标记 |
| 状态回退 | `statusAutoDriven = true` 的 IP 自动回退 `free` |
| 用户干预的 IP | 手动设置过状态的 IP 保持原状态 |

这避免了设备删除后遗留大量「已使用但无主」的僵尸地址。

## 在线探测

### 探测原理

```
对目标 IP 发起 ICMP Ping
        │
   ┌────┴────┐
 成功       失败
   │          │
   标记      按配置端口列表尝试 TCP 连接
  online       │
        ┌─────┴─────┐
      任一端口通   全部失败
        │            │
      online       offline
```

- `probeMethod` 记录成功方式：`ping`、`tcp`、`both`
- `probeLatency` 记录延迟（毫秒）
- 未探测过的地址为 `unknown`

### 探测配置

在网段详情页点击「探测设置」：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用 Ping | 开 | 关闭后仅使用 TCP 探测 |
| TCP 端口 | `22, 80, 443, 161, 3389` | Ping 被防火墙拦截时的回退探测 |
| 超时 | 1500 ms | 最小 200 ms |
| 并发数 | 20 | 范围 1~100，过大可能被设备侧限流 |

### 探测方式

| 方式 | 入口 | 适用场景 |
|------|------|----------|
| 单地址探测 | IP 行操作 | 排查单个地址 |
| 批量探测 | 选中多个 IP | 核对某批次地址 |
| 按网段探测 | 网段详情页「探测网段」 | 梳理整个子网 |
| 全量探测 | 探测设置面板「立即执行」 | 定期全面核对 |

### 定时探测

在「探测设置 → 定时探测」中开启并配置 Cron 表达式，默认 `0 3 * * *`（每天凌晨 3 点）。

| 特性 | 说明 |
|------|------|
| 热重载 | 保存后调度器立即生效，无需重启服务 |
| 部分更新 | 可只改开关或只改表达式，未提交项保持原值 |
| 执行方式 | 后台异步执行，不阻塞界面 |

> **部署注意**：定时任务由进程内 node-cron 驱动，**服务重启期间不会执行**。多实例部署时每个实例都会触发，需通过配置保证仅一个实例启用。

## 冲突排查

### 网段冲突

创建网段时如提示冲突，提示信息会指明冲突的网段名称与 CIDR。处理方式：

| 情况 | 处理 |
|------|------|
| 确实是新的子网划分 | 调整父网段选择，或修改 CIDR 前缀长度 |
| 误将已存在网段重复创建 | 直接使用已有网段 |
| 历史数据本身存在重叠 | 通过 `GET /api/ipam/conflicts` 全局排查后修正 |

### IP 冲突

IP 地址在网段内唯一。若导入的历史台账中存在重复地址：

1. 优先保留有设备绑定的记录
2. 无绑定的重复记录可直接删除
3. 确认无误后重新执行探测核对在线状态

## 与设备管理的联动

| 入口 | 位置 | 用途 |
|------|------|------|
| 设备详情 → IP 信息 | 设备管理 / 设备详情抽屉 | 查看该设备绑定的所有 IP |
| IP 列表 → 设备列 | IPAM 页面 | 点击设备名跳转设备详情 |
| 设备删除 | 设备管理 | 自动解绑并回退 IP 状态 |

## 典型使用流程

### 新机房上线

```
1. 创建机房记录 → 创建网段（按业务域划分，设置默认用途）
2. 创建设备 → 录入设备基础信息
3. 为设备绑定 IP（或批量导入设备后批量绑定）
4. 开启定时探测 → 次日核对在线状态
5. 对异常地址逐个排查（可能为台账错误或设备下线）
```

### 日常地址分配

```
1. 在网段中筛选「空闲」状态的 IP
2. 优先选择与业务网段用途匹配的地址
3. 绑定到目标设备，填写自定义标签
4. 首次分配建议设为主 IP 以便其他模块引用
```

### 设备下架

```
1. 在设备管理中将设备转入空闲设备
2. IPAM 中对应 IP 的绑定关系保留（设备尚未删除）
3. 确认设备报废后删除设备 → IP 自动解绑并回退为空闲
```

## 常见问题

**Q：旧版本设备表单里的 IP 地址字段还需要填吗？**

不需要。v2.8.3 已将 `Device.ipAddress` 迁移至 IPAM 表，旧字段保留但已废弃。所有地址维护请统一在 IPAM 模块中进行。

**Q：为什么父网段的使用率比子网段还高？**

父网段统计为递归累加值，包含所有后代网段的已用数。若父网段直接挂载的 IP 较少但子网段占用较多，父网段使用率会相应偏高，这是预期行为。

**Q：探测结果显示 offline，但设备实际在线？**

常见原因：ICMP 被安全策略拦截，且配置的 TCP 端口在目标设备上均未开放。处理：调整 TCP 端口列表，或在网络中放通 ICMP。

**Q：能否把一个 IP 绑定到多台设备？**

不能。IP 与设备为一对一关系。如需表达 VIP 等共享地址场景，建议使用 `customTag` 标注并在描述中说明主备关系。
