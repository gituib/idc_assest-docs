# 设备二维码信息牌

设备二维码信息牌用于将设备基础信息打印后贴附在机柜设备上，现场人员扫码即可查看设备身份，无需登录系统，也无需翻阅台账。

> **版本要求**：需 **v2.6.0 及以上**。

## 功能定位

| 传统方式 | 二维码信息牌 |
|----------|--------------|
| 手写标签，易脱落、字迹模糊 | 打印即贴，信息可随时重新生成 |
| 查设备信息需登录系统 | 扫码直接查看，无需账号 |
| 多台设备逐一核对效率低 | 支持批量生成与整页打印 |

## 单设备二维码

### 操作路径

```
设备管理 → 找到目标设备 → 操作列「二维码」
```

### 弹窗功能

弹窗采用左右布局：

| 区域 | 内容 |
|------|------|
| 左侧 | 信息牌实时预览（字段勾选变化即时反映） |
| 右侧 | 对外展示字段勾选列表 |
| 底部 | 下载 PNG / 打印 A4 / 复制二维码链接 |

### 可选字段

| 字段 | 默认勾选 | 是否可取消 | 说明 |
|------|----------|------------|------|
| 设备编号 | 是 | **否** | 核心标识，强制包含，保证扫码唯一绑定设备 |
| 名称 | 是 | 是 | 设备名称 |
| 类型 | 是 | 是 | 服务器 / 交换机 / 路由器 / 存储设备 |
| 型号 | 是 | 是 | - |
| 序列号 | 是 | 是 | 资产标识 |
| 所在位置 | 是 | 是 | 机房 / 机柜 / U 位 |
| 状态 | 是 | 是 | 运行中 / 维护中 / 离线 / 故障 / 空闲 |
| IP 地址 | **否** | 是 | 见下方安全说明 |
| 描述/备注 | **否** | 是 | 见下方安全说明 |

### 输出方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| 下载 PNG | 导出信息牌图片 | 发送给打印店批量制作、贴入文档 |
| 打印 A4 | 浏览器打印，自动适配 A4 版式 | 现场直接打印 |
| 复制链接 | 复制二维码内的 URL | 发送给同事，或粘贴到其他系统 |

## 批量二维码与打印

### 操作路径

```
设备管理 → 勾选多台设备 → 批量操作「二维码」
```

### 与单设备模式的差异

| 项 | 单设备 | 批量 |
|----|--------|------|
| 字段配置 | 可自定义 | 顶部统一勾选，应用到全部卡片 |
| 预览 | 单个大图 | 卡片区横向换行排列，可滚动 |
| 打印 | 单张 A4 | 一页多张，专用打印样式 |

### 打印样式隔离

同一页面可能同时存在多个二维码预览区域。批量打印期间，组件会给 `body` 添加 `qr-batch-printing` 标记类，打印样式据此**只输出批量打印区域**，隐藏其他预览区域，避免打印出意外的内容。

## 二维码内容与部署要求

### URL 结构

```
{当前站点 origin}/p/devices/{deviceId}?fields={勾选字段，逗号分隔}
```

示例：

```
https://idc.example.com/p/devices/SRV-0001?fields=deviceId,name,type,model,serialNumber,position,status
```

### 关键部署要求

> **二维码内嵌的是绝对地址，由生成时的浏览器 `window.location.origin` 决定。**

这意味着：

| 情况 | 后果 |
|------|------|
| 生成时使用 `localhost` 访问 | 打印出的二维码指向 `http://localhost:8000/...`，其他设备扫码无法访问 |
| 生成时使用内网 IP，扫码人在同一内网 | 正常 |
| 生成时使用正式域名 | 正常，推荐 |

**正确做法**：在正式域名可访问后（或至少使用将被长期使用的内网域名 / IP）再生成并打印二维码。

### 服务端对应端点

二维码指向的 `/p/devices/{deviceId}` 是**完全免鉴权**的公开页面，详见 [公开设备信息牌](/api/system-observability#公开设备信息牌)。

## 安全说明

### 字段白名单机制

公开页面**不接受任意字段**，仅渲染白名单内的固定字段：

```
deviceId, name, type, model, serialNumber, position, status
```

即使 URL 中显式指定 `?fields=ipAddress,description`，服务端也会忽略这些字段。

### 为什么默认不含 IP 地址与备注

| 风险 | 说明 |
|------|------|
| IP 地址泄露网络位置 | 内网 IP 段本身即暴露网络架构信息 |
| 备注可能含敏感内容 | 运维备注常含「待报废」「涉密项目」「临时借用」等内部信息 |
| 扫码人不可控 | 信息牌贴在现场，任何经过的人都能扫 |

若确有在信息牌上展示 IP 的需求，请在勾选时确认该机房的人员进出管控足够严格。

### 输出转义

服务端渲染 HTML 前对所有字段执行 HTML 转义，防止设备名称或备注中的特殊字符造成 XSS。

## 典型使用流程

### 新机房设备上架后批量贴牌

```
1. 确认系统部署在长期使用的域名 / IP 上
2. 设备管理 → 筛选本批新设备 → 批量选中
3. 批量二维码 → 勾选展示字段（默认即可）
4. 预览确认无误 → 打印
5. 现场贴附到设备前面板或机柜侧方
```

### 已有标签的替换

```
1. 逐个生成，或按机柜批量生成
2. 下载 PNG 后统一排版印刷
3. 保留原标签至新标签验证无误
```

## 常见问题

**Q：扫码后显示「设备不存在」？**

可能原因：
1. 二维码生成时设备尚未保存到数据库
2. 设备已被删除
3. 设备编号包含特殊字符导致 URL 编码异常

处理：重新生成二维码。

**Q：扫码后页面样式错乱？**

公开页面为独立 HTML，不使用前端框架资源。若显示异常，通常为浏览器缓存了旧版本页面，强制刷新即可。

**Q：能否在信息牌上加公司 Logo？**

当前信息牌由服务端 HTML 模板渲染，不含 Logo。如需定制，可修改 `backend/routes/public.js` 中的 `renderCardHtml` 模板。

**Q：批量打印时只打出了第一页？**

在浏览器打印对话框中确认「缩放」设置为「适应页面大小」，并检查纸张是否为 A4。批量区采用横向换行布局，每页容纳数量取决于浏览器缩放比例。

**Q：二维码能否打印在金属设备表面？**

普通纸张贴附在金属表面易脱落。建议使用工业级标签纸 + 覆膜，或打印在 PET 材质标签上。
